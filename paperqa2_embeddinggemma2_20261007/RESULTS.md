# EmbeddingGemma 2 검색 실험 결과

실행일: 2026-10-07 KST. 12편·862개 청크. 한국어 단독, 영어 단독, 한영 결합을 별도로 평가했다.

EmbeddingGemma 2의 @25 성적은 다중논문에서 한국어 10/30, 영어 13/30, 한영 결합 12/30이다. Gold에서는 각각 31/41, 36/41, 35/41이다. 이 데이터에서는 영어 단독이 가장 높았고, 한영 결합이 영어 단독보다 좋지는 않았다.

이번 설정에서 EmbeddingGemma 2 전체 교체는 Qwen 4B·8B보다 낮은 검색 적중률을 보였다. 한국어 Qwen 4B를 유지하고 영어만 EmbeddingGemma 2로 교체한 G는 다중논문 22/30, gold 39/41이다. 따라서 현재 평가만으로 기존 검색 모델의 전체 교체를 권장하기는 어렵다.

## 자원 사용

- 장치: NVIDIA GeForce RTX 3090 Ti
- EmbeddingGemma 2 모델 로딩 2.46초, 문서 862개 임베딩 57.01초, 질의 150개 임베딩 9.84초.
- 최대 GPU 할당 메모리 0.662 GiB. PyTorch가 할당한 메모리 기준이며 드라이버·다른 프로세스 메모리는 포함하지 않는다.
- 문서 벡터 2,648,064 bytes, 질의 벡터 460,800 bytes. float32 배열 기준.
- 다른 모델은 기존 문서 및 일부 질의 벡터를 재사용했으므로 전체 임베딩 속도 배수로 비교하지 않는다. 다운로드·로딩·소규모 검증 시간은 본 임베딩 시간과 분리했다.

## 설정과 한계

- Gemma: 텍스트 전용, 768차원, BF16, SDPA, 배치 1, SearchQuery/Document 공식 프롬프트. Qwen: 공식 검색 질의 프롬프트, BGE: 무프롬프트.
- 전체 청크 대상 코사인 검색, 동점은 원본 청크 순서. 한영 결합은 각각 top25 → RRF(60, 1:1) → 최종 top25.
- v2 정답·번역과 gold 영어 번역은 기존 사람 검수 대기 상태를 유지한다. 검색 적중률이며 생성 답변 정확도를 뜻하지 않는다.
- 제외된 gold 문항: q09, q15, q24, q23; 고정 코퍼스에 정규화된 정답 구절이 없음.
- 유료 API 호출 0회. 답변 생성과 RCS 없음. 30문항·41문항의 탐색적 비교로 작은 차이를 일반적인 우위로 해석하지 않는다.
- [Google 공식 모델 정보](https://huggingface.co/google/embeddinggemma-2)

## 검증과 재실행

- 기존 A~D의 120개 문항별 순위·채점을 재현했다. 별도 검증 결과는 `validation.json`을 확인한다.
- `inputs/query_order.json`: 실제 질의 텍스트와 순서. `indexes/`: 벡터와 출처. `results/multi/`, `results/gold/`: 15개 조건별 순위·채점.
- 새 환경의 Python으로 `src/embed.py gemma`, 기존 multilingual 환경의 Python으로 `src/embed.py q4`, `q8`, `bge`를 순서대로 실행한다. 이어 기존 환경에서 `src/evaluate.py`, `src/verify.py`를 실행한다.
- 기존 환경은 변경하지 않았다. 새 환경은 기존 패키지의 독립 복사본에 Transformers 5.19.0을 설치했다. Gemma 환경과 baseline 환경의 버전은 각각 manifest에 기록했다.
