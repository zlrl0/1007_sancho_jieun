# EmbeddingGemma 2 임베딩 비교 실험 계획

작성일: 2026-10-07 KST  
상태: 2026-10-07 한국어 단독·영어 단독·한영 결합 실행 및 검증 완료. 결과는 `RESULTS.md` 참조.

`google/embeddinggemma-2`로 기존 논문 검색용 임베딩을 교체했을 때 검색 품질과 자원 사용량이 어떻게 달라지는지 평가한다. 기존 12편의 논문과 862개 청크를 유지하고, 최근 Qwen 4B·8B 및 BGE-m3-ko 실험과 같은 질문·채점 기준으로 비교한다. 사용자 후속 요청에 따라 한국어 질문만 사용하는 조건과 영어 질문만 사용하는 조건을 별도 표와 파일로 저장하고 한영 결합과 함께 실행한다.

## 1. 실험 범위

1차 실험은 텍스트 임베딩과 검색 평가다. 그림은 기존 청크에 포함된 그림 서술 텍스트를 그대로 사용한다. PDF 재파싱, 청킹 변경, 질문 재번역, 정답 수정, BM25 결합, 재순위화, 답변 생성은 포함하지 않는다. 따라서 결과는 검색 성능을 의미하며 답변 정확도로 해석하지 않는다.

모델은 공식 모델 카드의 텍스트 전용 설정을 사용한다. 기본 출력은 768차원이며 질의는 `SearchQuery`, 문서는 `Document` 프롬프트를 적용한다. BF16을 지원하는 GPU에서는 BF16, 그 외에는 FP32를 사용하고 FP16은 사용하지 않는다. 공식 컨텍스트 한도는 8,192토큰이다. [Google 공식 모델 카드](https://huggingface.co/google/embeddinggemma-2)

## 2. 고정할 데이터와 비교 기준

경로는 모두 `benchmark/` 기준이다.

| 용도 | 입력 | 평가 규모 |
|---|---|---|
| 공통 코퍼스 | `chunks/chosen_SEC_none.jsonl` | 논문 12편, 청크 862개 |
| 주 평가 정답 | `paperqa2_retrieval_expanded_20261004/v2/questions_ko_en.json` | 다중논문 30문항 |
| 주 평가 질의 | `paperqa2_retrieval_expanded_20261004/v2/retrieval_queries.json` | 한국어·영어 60개 질의 |
| 보조 평가 원본 | `gold_45.json` | gold 45문항 |
| 보조 평가 번역과 매핑 | `paperqa2_gold45_embed_compare_20261005/inputs/questions_ko_en.json` | 기존 매핑 가능한 41문항을 주 분모로 사용 |

보조 평가는 45문항 전체의 처리 상태를 남기고, 매핑되지 않은 4문항은 제외 사유와 ID를 명시한다. 41문항 성능과 전체 45문항의 매핑 범위를 함께 보고한다. 한국어·영어 질의만 사용하며 추가 원문 언어 조건은 이번 범위에 넣지 않는다.

v2 정답과 번역은 기존 실험에서 사람 검수 대기 상태이며, gold 평가의 영어 번역도 검수 상태를 그대로 기록한다. 두 평가군은 합산하지 않는다. 실행 직전에 입력 SHA-256, 질문·청크 순서와 개수를 고정한다.

## 3. 비교할 조건

### 단일 언어 검색

EmbeddingGemma 2, Qwen3-Embedding-4B, Qwen3-Embedding-8B, BGE-m3-ko를 한국어와 영어 각각 평가한다. 모든 모델은 자기 모델로 만든 문서·질의 벡터끼리 코사인 검색한다. 모델별 기본 차원을 유지하며 서로 다른 모델의 벡터를 직접 비교하지 않는다.

### 한영 검색 결합

각 언어에서 상위 25개를 검색한 뒤 RRF로 최종 25개를 선택한다. RRF 상수는 60, 언어별 가중치는 1:1이다. 점수는 각 검색 목록의 1부터 시작하는 순위에 대해 `1 / (60 + rank)`를 합산하고, 목록에 없는 청크는 해당 목록에서 0점을 받는다. 동점은 원본 청크 순서로 처리한다.

| 조건 | 한국어 모델 | 영어 모델 | 비교 목적 |
|---|---|---|---|
| 기준 A | Qwen 4B | BGE-m3-ko | 최근 혼합 모델 기준 |
| 기준 B | Qwen 8B | BGE-m3-ko | 대형 모델 혼합 기준 |
| 기준 C | Qwen 4B | Qwen 4B | 단일 모델 기준 |
| 기준 D | Qwen 8B | Qwen 8B | 대형 단일 모델 기준 |
| 신규 E | EmbeddingGemma 2 | EmbeddingGemma 2 | 전체 임베딩 교체 효과 |
| 신규 F | EmbeddingGemma 2 | BGE-m3-ko | A·B의 한국어 모델 교체 효과 |
| 신규 G | Qwen 4B | EmbeddingGemma 2 | A의 영어 모델 교체 효과 |

주 비교는 **E 대 C·D**, 보조 비교는 **F 대 A·B**, **G 대 A**로 사전 고정한다. 최근 주 평가 기준값은 A 23/30, B 22/30, C 22/30, D 23/30 FullHit@25다. [기존 결과](../paperqa2_qwen4b8b_official_prompt_20261007/RESULTS.md)

기존 벡터는 모델 revision, 프롬프트, 입력 해시와 ID 순서가 일치할 때 재사용한다. 저장된 top20 결과만으로 top25를 만들지 않고 벡터에서 다시 순위를 계산한다. Qwen은 최근 공식 질의 프롬프트 조건에 맞춘다. 특히 gold 실험의 과거 Qwen 질의 캐시가 무프롬프트 조건이면 그대로 비교하지 않고 공식 프롬프트로 질의만 재계산한다. 이 경우 추가 계산을 실행 기록에 남긴다.

## 4. EmbeddingGemma 2 실행 설정

| 항목 | 계획 |
|---|---|
| 모델 ID | `google/embeddinggemma-2` |
| 모델 버전 | 실행 시 실제 commit SHA를 확인하고 고정 |
| 입력 모달리티 | 텍스트만, `config_kwargs={"vision_config": null, "audio_config": null}`에 대응하는 Python 설정 사용 |
| 질의 | `prompt_name="SearchQuery"` |
| 문서 | `prompt_name="Document"`, 원본 청크 텍스트 사용 |
| 제목 | 별도 논문·절 제목을 추가하지 않음. 기본 Document의 제목 없음 형식 사용 |
| 프롬프트 검증 | 다운로드한 설정의 실제 문자열을 기록하고 중복 삽입 여부 확인 |
| 출력 | 768차원, L2 정규화, float32 저장 |
| 추론 | CUDA BF16 지원 확인 후 BF16, 미지원이면 FP32 |
| 배치 | 기존 조건과 맞춰 1로 시작 |
| 검색 | 정규화 벡터 내적, 전체 862개 대상, 문서 사전 필터 없음 |
| 재현성 | 패키지 버전, 모델 revision, 장치, attention 구현, 난수 seed, 입력 해시 기록 |

현재 확인한 GPU는 NVIDIA GeForce RTX 3090 Ti, 총 메모리 24,564 MiB다. 실제 실행 시 사용 가능 메모리를 다시 확인한다. 새 폴더에 독립 가상환경과 모델 캐시를 두고 기존 환경의 패키지를 변경하지 않는다. 필요한 라이브러리 버전은 작은 로딩 검증을 통과한 뒤 잠근다.

기존 청크의 토큰 수는 다른 토크나이저 기준이므로, 모든 청크와 질의를 새 모델의 토크나이저로 다시 센다. 프롬프트와 특수 토큰을 포함해 실제 허용 길이를 초과하면 조용히 잘라내지 않고 해당 ID와 길이를 보고한다. 초과 입력이 있으면 본 실험을 보류하고 별도의 긴 입력 처리 조건을 정한다. 이번 기본 비교에는 임의 분할이나 평균 풀링을 추가하지 않는다.

## 5. 평가 지표와 해석

- **주 지표:** 다중논문 30문항의 FullHit@25. 모든 필수 논문에서 허용 근거 청크를 하나 이상 찾은 문항 수와 비율이다. 기존 `hit()`의 대체 청크 인정 규칙을 유지한다.
- **보조 지표:** FullHit@5·10·20, 문항별 필수 논문 적중 비율의 평균, 전체 필수 논문 근거 적중 수. 한국어·영어 단독 검색도 별도 보고한다.
- **gold 평가:** 매핑된 41문항의 Hit@5·10·20·25와 MRR@25. 허용 근거의 첫 순위를 사용하고 25위 밖은 0으로 계산한다. 다중논문 FullHit와 구분한다.
- **문항별 변화:** 신규 적중, 적중 상실, 순위 변화, 관련 청크 ID를 비교한다. 문서 언어별 오류를 살피고 작은 하위집단에는 분모를 명시한다.
- **효율:** 모델 로딩 시간, 문서·질의 임베딩 시간, 검색 시간, GPU 최대 할당 메모리, 벡터 파일 크기를 기록한다. 다운로드 시간과 로딩·추론 시간을 구분한다.

정확히 일치한 데이터와 설정에서 기존 A~D의 순위·점수가 재현되어야 비교 결과를 확정한다. 과거 캐시 생성 시간과 신규 추론 시간을 직접 속도 배수로 비교하지 않는다. 동일 장비·조건에서 다시 측정하지 않은 속도는 참고값으로만 표기한다.

EmbeddingGemma 2의 주 지표가 기준보다 낮으면 손실 문항을 명시하고, 같거나 높으면 자원 사용량과 보조 지표를 함께 검토한다. 30문항에서 1문항 차이는 약 3.33%p이므로 작은 차이를 일반적인 우위로 해석하지 않는다. 결과를 본 뒤 프롬프트를 바꾸어 주 실험 결과를 대체하지 않는다.

## 6. 실행 순서와 완료 조건

1. **입력 고정:** 원본 해시·질문 수·청크 수·정답 매핑·비교 캐시 출처를 검증한다.
2. **환경 검증:** 별도 환경에 모델을 준비하고 revision과 패키지 버전을 기록한다. 전체 입력 길이를 검사한 다음 대표적인 한국어·영어·긴 청크로 소규모 추론을 검증한다.
3. **임베딩 생성:** 문서 862개, 주 평가 질의 60개, 보조 평가 한영 질의 90개를 생성한다. 중복 텍스트를 캐시하더라도 각 질의 ID와 대응 관계를 유지한다.
4. **검색과 채점:** 단일 언어와 A~G 결합 검색을 평가하고 문항별 근거를 저장한다.
5. **결과 검증:** 벡터 차원·유한값·정규화·ID 정렬, 중복·누락, 채점 함수의 적중·부분 적중·실패 예시, 기존 결과 재현, 원본 해시 불변을 확인한다.
6. **보고:** 비교표, 신규 적중·상실 문항, 효율 측정, 실패·제외 조건, 재실행 방법을 정리한다.

NaN/Inf, 0 벡터, 모델 ID 불일치, 입력 길이 초과, 해시 불일치, 비교 기준 재현 실패가 있으면 해당 단계를 실패로 기록한다. 일부 결과만 생성된 실행을 완료로 표시하지 않는다. 정답·근거·answer span은 채점에만 사용하고 모델 입력에는 넣지 않는다.

1차 실험의 유료 LLM API 호출은 0회다. 실행 시간과 다운로드 용량은 모델 준비 및 소규모 검증 후 추정한다. 답변 생성과 RCS 평가는 검색 결과를 확인한 뒤 별도 후속 계획으로 다룬다.
