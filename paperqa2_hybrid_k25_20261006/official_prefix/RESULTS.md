# PaperQA2 공식 hybrid 접두사와 dense 검색 비교 결과

실행 및 정리일: 2026년 10월 6일

## 결론과 선택

**이번 실험에서 hybrid가 dense보다 더 좋다는 결과는 나오지 않았다. 정답 근거 적중 성능은 같았다. 새로 기본 구성을 선택한다면 dense + RRF를 권한다.**

이는 dense의 성능이 더 높다는 뜻이 아니다. 확인된 검색 성능이 같은 상황에서 추가 sparse 구성을 사용할 이득이 입증되지 않았으므로, 단순한 구성을 기본으로 택하자는 운영 판단이다. 이미 hybrid를 사용하는 경우 이번 결과만으로 반드시 제거해야 할 이유도 없다.

| 판단할 내용 | 이번 결과로 말할 수 있는 것 |
|---|---|
| hybrid가 정답 근거를 더 많이 찾았나? | 아니다. 추가로 찾거나 잃은 정답 논문 항목이 없었다. |
| dense가 검색 성능에서 더 좋았나? | 아니다. 측정한 근거 적중 지표는 같았다. |
| hybrid가 최종 답변을 더 잘 만들었나? | 평가하지 않았다. 이번 실행에는 답변 생성이 없다. |
| 무엇을 기본으로 선택할까? | 현재 근거로는 dense + RRF. hybrid도 사용 가능하지만 성능 향상을 이유로 선택할 근거는 부족하다. |
| hybrid를 쓰면 유료 API 비용이 더 드나? | 이번 두 로컬 모델과 sparse 계산에는 유료 API 호출이 없었다. 로컬 계산량과 벡터 저장량은 늘어난다. |

## 실행 방법

이 문서는 `official_prefix`에 저장된 실제 모델 재실행 결과를 정리한다. 상위 폴더의 기존 `RESULTS.md`는 이전 캐시 기반 결합 실험의 기록이다.

| 항목 | 설정 |
|---|---|
| 한국어 질문 모델 | `hybrid-st-Qwen/Qwen3-Embedding-4B` |
| 영어 질문 모델 | `hybrid-st-dragonkue/BGE-m3-ko` |
| 모델 생성 | PaperQA2 `Settings(embedding=...).get_embedding_model()` |
| 문서 및 질문 | 논문 12편, 청크 862개, 다중논문 질문 30개와 그 한·영 표현 |
| 임베딩 실행 | 두 모델로 전체 문서와 언어별 질문 30개를 실제 재계산 |
| sparse | PaperQA2 기본 token-modulo sparse 256차원 |
| 검색 | 코사인 유사도로 언어별 상위 25개 |
| RRF | 동일 가중치, 상수 60, 동점은 코퍼스 순서 |
| 최종 검색 목록 | RRF 상위 25개 |
| 실행 장치 | GPU, batch size 1 |
| 질문 프롬프트 | 별도 instruction 없이 설치된 어댑터 기본값 사용 |
| 답변 생성 | 실행하지 않음 |

두 조건은 같은 새 dense 벡터를 공유하도록 구성했다.

- **D0 dense + RRF:** 새 hybrid 벡터에서 dense 부분만 사용하여 검색하고 한·영 순위를 합산한다.
- **H1 hybrid + RRF:** 새 hybrid 벡터 전체로 검색하고 한·영 순위를 합산한다.

따라서 D0는 별도 모델을 다시 로딩한 결과가 아니라, hybrid가 생성한 동일 dense 부분을 사용하는 비교군이다. 이렇게 하면 이번 실행 안에서 sparse 추가 여부를 비교할 수 있다.

## 검색 결과

| 조건 | 완전 적중 문항 | 완전 적중률 | 필수 논문 근거 적중 | 필수 논문 근거 적중률 | 문항별 부분 점수 평균 |
|---|---:|---:|---:|---:|---:|
| 새 D0 dense + RRF | 22/30 | 73.3% | 71/82 | 86.6% | 87.8% |
| 새 H1 hybrid + RRF | 22/30 | 73.3% | 71/82 | 86.6% | 87.8% |
| 기존 캐시 기반 hybrid + RRF | 22/30 | 73.3% | 71/82 | 86.6% | 87.8% |

완전 적중은 해당 질문이 요구하는 모든 논문에 대해 정답 청크 또는 허용된 대체 청크를 하나 이상 찾은 경우다. 필수 논문 근거 적중은 질문과 필수 논문의 82개 조합 중 성공한 수다. 부분 점수는 각 질문에서 필요한 논문 근거를 찾은 비율을 계산한 뒤 질문별로 평균한 값이므로 71/82와 분모가 다르다.

**합계만 같은 것이 아니라, 30문항 각각의 완전 적중 여부와 논문별 적중 여부도 D0와 H1 사이에서 모두 같았다.** 새 H1과 기존 캐시 기반 H1의 문항별 채점 결과도 모두 같았다.

## 검색 목록은 바뀌었는가

바뀌었다. 정답 근거 적중이 같다는 것이 검색 목록이나 순서까지 같다는 뜻은 아니다.

| 비교 | 확인한 차이 |
|---|---|
| 새 dense 대 새 hybrid | 최종 25개 중 평균 23.23개 공유. 문항당 평균 약 1.77개가 다른 청크로 교체됨 |
| 새 hybrid 대 기존 hybrid | 최종 25개 중 평균 24.73개 공유. 30문항 중 22문항은 청크 집합이 동일 |
| 새 dense 대 기존 고정 dense 목록 | 30문항 중 8문항만 순서까지 동일 |

이번 재임베딩에서 한국어 Qwen은 bfloat16, 영어 BGE-m3-ko는 float32로 실행되었다. 이전 캐시와 새 실행의 정밀도 및 인코딩 경로 등이 달라질 수 있으므로, 접두사로 바꾸면 기존 순위를 완전히 재현한다고 가정해서는 안 된다. 위 목록 차이의 원인을 따로 분리하여 검증하지는 않았다.

검색 목록과 순서가 달라졌으므로 향후 답변 결과도 달라질 수 있다. 그러나 이번 실행으로 답변 품질의 개선이나 악화를 판정할 수는 없다.

## 비용과 한계

유료 API 호출은 0회다. Qwen과 BGE-m3-ko 모델을 실제 로드하여 GPU로 임베딩했다. hybrid 벡터는 Qwen 2,816차원, BGE-m3-ko 1,280차원으로, 각각 dense에 sparse 256차원이 추가되었다.

실행 시간과 메모리 사용량을 dense 단독 실행과 별도로 측정하지 않았으므로, hybrid의 추가 지연이나 자원 비용을 수치로 비교하지는 않는다.

이번 결과는 하나의 코퍼스와 30문항, top25 조건의 검색 평가다. 다른 질문, 검색 깊이, sparse 가중치 또는 차원에서의 우열로 일반화하지 않는다. 동일한 적중 수가 통계적 동등성이나 무해함의 증명은 아니다.
